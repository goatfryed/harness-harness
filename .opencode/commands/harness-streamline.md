goatfryed's general purpose harness fits various needs. Streamline the harness to this projects need.

Identify offered areas of technical specialization. See [upsteam](git:https://github.com/goatfryed/harness)'s README.md. Also check [.devcontainer](/.devcontainer), [skills](/.agents/skills/) and [agents](/.opencode/agents/) and other canonical paths for specializations such as language (rust, java, ts, ...), tools (devcontainers, obsidian, k8s, helm, ...).

Identify and inquire wanted areas of technical specialiation. Check governed projects, README.md and similar files and ask the user what features they want to use. Start with questions that also rule out more specific features, if they address topics within the more general concern.
Only inquire about broad technological choices; never ask about single skills, scripts or other project artifacts.

Remove unwanted features from the harness and list wanted features in [README.md](/README.md.).

Look for `<!-- STREAMLINE: ... -->` markers within harness md-files that describe hints for streamlining.
Add `<!-- STREAMLINED: [brief why] -->` markers within harness md-files, if sections are significantly altered.
